# Agent Instructions: Kodi Addon Repository (GitHub Pages)

You are an expert developer assistant specialized in Kodi addon repository
maintenance, XML metadata generation, static web hosting via GitHub Pages, and
Git workflows. Follow these strict core guidelines for all interactions on this
project.

## 1. Project & System Context

- **Purpose:** A centralized Kodi Addon Repository hosted via GitHub Pages that
  distributes and auto-updates custom Kodi addons (e.g., Stardima plugin) and
  their repository metadata (`addons.xml`, `addons.xml.md5`).
- **Target Environment:** NixOS Linux. All terminal commands, paths, and build
  scripts must conform to a standard Linux environment.
- **Debugging & Deployment:** Verify hosted endpoints via HTTP status checks or
  `curl` against the GitHub Pages URL, and monitor Kodi client logs at
  `~/.kodi/temp/kodi.log` when testing addon installs directly from the
  repository.

## 2. Versioning & Git Workflow

- **Semantic Versioning:** Strictly follow
  [Semantic Versioning 2.0.0](https://semver.org/). Format: `MAJOR.MINOR.PATCH`.
  Apply version bumps to both individual addon `addon.xml` manifests and the
  main repository addon itself.
- **Initial Versioning Constraint:** Always keep the major version set to `0`
  (`0.x.y`) for initial releases and development iterations. Do NOT bump the
  major version to `1.0.0` or higher unless explicitly instructed by the user.
- **Git Commit Messages (Gitmoji):** Use [Gitmoji](https://gitmoji.dev/)
  conventions for all Git commit messages. Prefix every commit message with the
  appropriate emoji or shortcode corresponding to the intent of the change
  (e.g., `:sparkles:` / ✨ for features, `:bug:` / 🐛 for fixes, `:pencil2:` /
  ✏️ for docs, `:recycle:` / ♻️ for refactoring).
- **Auto-Tagging:** As soon as the user accepts changes, says "it's great,"
  "good," or otherwise approves a feature or release, immediately prepare or
  execute a Git tag corresponding to the new repository/addon version.
- **Changelog Management:** Update `CHANGELOG.md` concurrently with every
  version bump, strictly following the
  [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/) format.

## 3. Documentation & Manifest Maintenance

- **Addon Manifests (`addon.xml`):** Ensure every addon directory contains a
  valid `addon.xml` file with accurate version numbers, dependencies, and
  metadata.
- **README Updates:** Automatically update the repository `README.md` file
  whenever a new addon is added, an existing addon is updated, or the GitHub
  Pages URL/instructions change.

## 4. Repository Build & Generator Verification

- **Metadata Sync:** Always run the repository generator script (e.g.,
  `addons_xml_generator.py` or equivalent build task) whenever an addon is
  modified or added. This regenerates the root `addons.xml` and `addons.xml.md5`
  checksum files.
- **Zip Structure Check:** Verify that generated plugin ZIP files (e.g.,
  `plugin.video.stardima-X.Y.Z.zip`) place the root addon folder inside the
  archive, excluding all `.git`, OS dotfiles, and development artifacts.
- **Verification Rule:** Never push changes to the repository branch without
  confirming that `addons.xml` contains the latest addon versions and
  `addons.xml.md5` matches the regenerated file hash.

## 5. Deployment & Testing Workflow

When preparing a release or deploying updates to GitHub Pages for live Kodi
testing:

### A. Build Repository Package

1. **Update Addon Source:** Place or update source code in the respective addon
   directory (e.g., `plugin.video.stardima/`).
2. **Execute Build Script:** Run the repository build tool to create/update
   zipped releases in the directory structure and refresh `addons.xml` +
   `addons.xml.md5`.
3. **Commit & Push:** Stage all updated ZIP files, metadata, and checksums using
   standard Git commits formatted with Gitmoji syntax, then push to the branch
   serving GitHub Pages (e.g., `main` or `gh-pages`).

### B. Live Kodi Testing

To test repository updates directly in Kodi:

1. **Clear Kodi Cache:** Force Kodi to refresh its repository cache by
   triggering a repository check or deleting
   `~/.kodi/userdata/Database/Addons37.db` (or equivalent database version) if
   stale data persists.
2. **Verify Stream / Install:** Install or update the addon directly from the
   hosted repository source inside Kodi, and verify video playback using local
   testing tools (`mpv`) if direct stream analysis is needed.

## 6. Problem Solving & Tooling

- **Web Research:** If you encounter issue handling Kodi XML schema changes,
  checksum generation bugs, or GitHub Pages deployment errors, proactively
  search for established patterns used by other Kodi repository maintainers.
- **HTTP Inspection:** Use CLI tools like `curl` or browser tools to inspect
  hosted `addons.xml` files and ensure CORS, mime types, and static paths serve
  correctly over GitHub Pages.
- **Documentation Tools:** Use `Context7` or available Kodi documentation tools
  to verify API schema compatibility for `addon.xml` tags and repository
  specifications.
